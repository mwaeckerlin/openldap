# Features

Numbered register of every feature; a number is never reused. The features were found in the image as it stood in 2022 and carried over into the headless rebuild. Every feature is covered by tests listed in [TESTS.md](TESTS.md); the guard `tests/docs-contract.sh` fails when a feature has no test.

- **F1 — LDAP server for one domain.** The server answers LDAP on port 389 for the directory of `DOMAIN`: `example.org` gives the base `dc=example,dc=org`. `DOMAIN` is mandatory; without it the container stops with «Specifying a domain is mandatory, use -e DOMAIN=example.org». The server does not create the base entry itself: the administrator, `INIT_LDIF`, `INIT_SCRIPT` or an administration front end such as LAM adds it.
- **F2 — Administrator.** `cn=admin,<base>` may read and write everything, with the password `PASSWORD`. A bind with another password is refused.
- **F3 — Durable data.** The directory lives in `/var/lib/ldap` and survives every restart and every recreation of the container that keeps the volume.
- **F4 — Generated password.** Without `PASSWORD` the image generates a password of 20 letters and digits on the first start, writes it once to the log as `password: <password>` and keeps it in `/etc/ldap/password`; every later start and the health check take it from there.
- **F5 — Access rules.** `ACCESS_RULES` holds the slapd access rules on one line, every rule starting with `access to`. The default `access to * by self write by users read by anonymous auth` lets every user read the directory and change his own entry, and lets an anonymous client do nothing but log in. Any other value replaces the default completely; `access to * by * read` opens the directory for anonymous reading.
- **F6 — Indexes.** `INDEXES` adds indexes to the default `index objectClass eq`, written as `index uid eq index cn eq,sub`; a leading space is allowed.
- **F7 — Group membership.** With `MEMBEROF=1` every member of a `groupOfNames` carries the attribute `memberOf` with the group, and deleting an entry removes it from the `member` list of every group. Default `0`: off.
- **F8 — Schemas.** `core` is always loaded; `SCHEMAS` names the others, default `cosine inetorgperson nis samba`, which the default configuration of LAM needs. The image carries the schemas of OpenLDAP (`cosine`, `inetorgperson`, `nis`, `misc`, `openldap`, `collective`, `corba`, `duaconf`, `dyngroup`, `java` among them) and three of its own: `samba` (Samba accounts and group maps), `openssh-lpk` (SSH public keys) and `ldapns` (LDAP name service). An entry with an object class of a schema not listed is refused. A name the image does not carry stops the container with `invalid SCHEMAS`.
- **F9 — Unprivileged server.** slapd runs as the user `ldap`, uid 102, member of the group `shared-access`, gid 500, never as root, and still listens on 389 and 636. Volumes and certificates belong to that uid, or are readable for that group.
- **F10 — Backup at every start.** Before the server starts on an existing directory, the whole directory is saved to `/var/backups/<YYYYMMDDHHMM>-startup-data.ldif` (date and time of the start). A failed backup stops the start.
- **F11 — Restore.** Exactly one file whose name ends in `data.ldif` in `/var/restore` replaces the whole directory on the next start; afterwards it is moved to `/var/backups/<YYYYMMDDHHMM>-restored-data.ldif`. Where `/var/restore` is read-only, the file stays, is restored again on every start, and the container still starts. A file that cannot be restored stops the start with «restore of <file> failed, the database stays as it was» and leaves the directory untouched; two or more such files stop the start until only one is left. No backup is written on a start that restores.
- **F12 — Initial entries and custom schemas.** `INIT_SCRIPT` names an LDIF file that is applied as the administrator on every start, once the server answers: new entries are added, records with `changetype` are applied, and an entry that already exists is reported and skipped. `CUSTOM_SCHEMAS` names a directory whose `*.schema` files, also in subdirectories, are loaded after the schemas of `SCHEMAS`. A path that does not exist is reported in the log and the server starts without it.
- **F13 — Log level.** `DEBUG` sets the slapd log level, as a number or a name such as `stats`; default `256` (`stats`): every connection and every operation is logged with its DN and result, never with a password.
- **F14 — TLS.** With a certificate for `DOMAIN` in `/ssl`, either `live/<DOMAIN>/cert.pem`, `privkey.pem` and `chain.pem` (the layout of Let's Encrypt) or `<DOMAIN>.pem`, `<DOMAIN>.key` and `<DOMAIN>-ca.crt`, the server answers LDAPS on port 636 and StartTLS on port 389, with TLS 1.2 or newer. Without a certificate only plain LDAP on 389 is served. A certificate file the user `ldap` cannot read stops the container with a message that names the file and the uid.
- **F15 — Health check in the image.** Docker reports the container healthy only while the administrator can bind on port 389, with `PASSWORD` or the stored password; a compose file or a Swarm stack needs no healthcheck of its own.
- **F16 — Clean stop.** `docker stop` ends slapd with a clean shutdown, and the container exits with status 0.
- **F17 — Validated configuration.** Every variable is checked before the configuration is written; a value that cannot be used, above all one with a line break that would add directives of its own, stops the container with `invalid <VARIABLE>`.
- **F18 — Headless.** The image carries slapd, its tools (`slapadd`, `slapcat`, `slapindex`, `slappasswd`, `slaptest`), `ldapmodify`, their libraries and the start program; no shell, no package manager.
- **F19 — Published for amd64 and arm64.** Every push builds the image natively for both architectures and publishes it under one tag on Docker Hub, with the reusable workflow of `mwaeckerlin/scratch`, and rebuilds it every week.
- **F20 — Database size.** `MAXSIZE` sets the largest size the directory may grow to, in bytes; default `10737418240` (10 GiB).
- **F21 — Build arguments.** An image built with `--build-arg overlays="<packages>"` carries the named OpenLDAP packages in addition; `--build-arg backend=<name>` installs the package `openldap-back-<name>` (default `mdb`, the backend the configuration uses).
- **F22 — Initial entries and custom schema in the environment.** The operator writes the initial entries and a schema of his own into the compose file and mounts nothing. `INIT_LDIF` holds LDIF text that is applied as the administrator on every start, once the server answers, with the same rules as `INIT_SCRIPT`: new entries are added, records with `changetype` are applied, an entry that already exists is reported and skipped. `CUSTOM_SCHEMA` holds schema text that is loaded after the files of `CUSTOM_SCHEMAS`. Both are empty by default and then change nothing. Where `INIT_SCRIPT` is set as well, its file is applied first. `INIT_LDIF` takes every text without control characters but tab and line break; `CUSTOM_SCHEMA` takes lines starting with `attributetype`, `objectclass`, `objectidentifier` or `ldapsyntax` (upper or lower case), indented continuation lines, blank lines and `#` comments, and any other line, such as `include` or `rootpw`, stops the container with `invalid CUSTOM_SCHEMA`.
